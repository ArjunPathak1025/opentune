# Contributing to OpenTune

Thanks for helping build OpenTune.

## Development workflow

1. Fork or clone the repository.
2. Create a focused branch from `main`.
3. Make a small, testable change.
4. Run formatting, linting, tests, and the relevant build locally.
5. Open a pull request with a clear description and testing notes.

## Pull requests

- Keep pull requests focused.
- Add or update tests for behavior changes.
- Update documentation when public behavior or architecture changes.
- Do not commit secrets, credentials, generated private data, or copyrighted music files.

## Commit messages

Use concise conventional-style commits such as `feat:`, `fix:`, `docs:`, `test:`, `refactor:`, and `chore:`.

## Media and licensing

Contributors must only add media assets and metadata that they have permission to distribute with the project. OpenTune is software for managing and playing music users own or are authorized to play.
